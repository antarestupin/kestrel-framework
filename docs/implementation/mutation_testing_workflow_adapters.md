# Workflow adapter mutation assessment

[Coverage inventory](./mutation_testing_inventory.md) · [Contributor commands](../contributing/mutation-testing.md) · [Workflow adapter contract](./workflows.md#adapter-api)

The November 11 review divides both built-in adapters into bounded ranges. Activation journal writes, admission, task reservation, activity completion and dispatch, history and persistence helpers, and adapter configuration/schema each have a focused profile. The earlier retry identity, ownership, and terminal-control assessments supply the remaining ranges. Each fresh execution uses the ten-minute budget and retains static mutants. The bounded runs are local observations and their scores remain informational.

## Reproduced defects

- **Partially committed memory activation.** A valid activity and child command were followed by a child ID conflict. The memory adapter rejected the request after publishing scheduled events, advancing the parent revision, and creating work from the prefix. A malformed later sequence also left the revision advanced, blocking a corrected request on the same reservation. The adapter now prepares the batch, including child admission and task identities, before publishing any journal or task changes. The PostgreSQL transaction already rolled back both the journal and the outbox in the equivalent test.
- **Generic PostgreSQL activation used the host clock.** With an application clock behind PostgreSQL, journal events received the host's timestamp and timers became eligible immediately. The adapter now reads the store clock after acquiring the activation locks. The regression shifts only the application clock and brackets stored event times with PostgreSQL readings.
- **Overlapping embedded compensations lost pending tasks.** After cancellation removed the original work, both adapters still deleted every older command task when a later activation scheduled more work. That deleted a still-pending compensation while a later compensation progressed. Both adapters now keep compensation work until its own completion or a terminal cleanup.
- **Worker outbox cancellation behaved differently between adapters.** Memory allowed unpublished pre-cancellation activity to run; PostgreSQL also blocked newly journaled compensation and could leave the workflow waiting. Both adapters now use the cancellation event's journal position to admit only compensation recorded after cancellation.
- **An older Worker result could complete a later generation.** Continue-as-new keeps the execution ID and resets the command sequence. In both adapters, a delayed first-generation result used to append a completion for the successor's command with the same sequence. Outbox reservations now identify their generation. Both adapters acknowledge a result from an older generation without changing the active journal, reject a future generation, and accept a matching one. An unversioned result for a later generation is accepted when its dispatch ID, execution ID, and sequence match the current outbox row.
- **Raw PostgreSQL reservation timestamps escaped as strings.** The task projection declared `Date` fields, but raw Drizzle results returned text. Timer and activity timing logic called `getTime()` on those fields. Both task and outbox reservations now normalize their dates at the adapter boundary.
- **Repeated PostgreSQL cancellation reached a new compensation child.** A second cancellation returned `false` for the parent while still marking its newly created child as cancelled. The adapter now leaves the child runnable, matching memory behavior.
- **Missing parent blocked memory termination.** A low-level execution may retain a parent link after the parent disappears. Memory changed the child's status but threw while resolving the parent, before finishing terminal cleanup. Memory now finishes closing the orphan, as PostgreSQL already did.
- **Caller-owned activity error details leaked into memory history.** Embedded and external activity completion now copy the error details before storing them. Changing the caller's command sequence metadata after completion no longer changes the journal.
- **Memory start batches missed an incompatible repeated ID on `return-existing`.** The earlier request attached to a different execution, so its requested ID was absent from the staging store. Repeating that ID with different input then succeeded. The adapter now tracks every first request, including aliases, and rejects incompatible repetitions before publishing the batch.
- **Memory start batches could publish half the batch if a later task ID allocation failed.** All activation IDs are now allocated before publishing executions or work, so a failed allocation leaves both requests available to retry.
- **PostgreSQL start batches conflated an unkeyed execution ID with a keyed request.** Equal text caused the unkeyed request to count against the keyed permit. A keyed request could be rejected, remain pending indefinitely, or fail its return-existing lookup depending on its policy. The admission window now partitions by business key, and all three policies have regression cases.
- **PostgreSQL search interpreted `_`, `%`, and backslashes as pattern syntax.** Search now matches literal case-insensitive substrings across execution IDs, definition names, and business keys, as the memory adapter already did.
- **A shared transient error could stop workflow polling.** Two aggregate branches wrapping the same connection failure were classified as a cycle and failed the poller. Cycle detection now tracks active ancestors, so true recursion still fails while independent branches may share a transient cause.
- **A parent could reuse a previous generation's default child ID.** Both adapters derived the child only from the logical parent ID and command sequence. The successor then reused a completed child and waited without enqueuing work. A generated child ID now includes the parent generation when it is greater than one. The regression preserves the previous child and observes a fresh activation for the successor's child.

The PostgreSQL test fixture now permits distinct signals without idempotency keys, matching the production index. The multi-command journal test verifies an unmatched signal, one buffered signal for two matching waits, preserved unmatched timers, ordered completion indices, and persisted null. Multi-connection cases use a separate schema per test process. Two concurrent executions of the PostgreSQL adapter suite completed independently.

## Scope decisions

The historical [task ownership](./mutation_testing_workflow_task_ownership_classification.json), [retry identity and input preservation](./mutation_testing_workflow_retry.md), and [PostgreSQL retry and lease ownership](./mutation_testing_postgres_ownership.md) measurements remain applicable to their selected ranges. Their tests cover stale and cross-task reservations, lease windows, original null input, competing start/retry identity and keyed capacity. Their remaining cases concern diagnostics, redundant guards, additional work or fallback rows that a healthy built-in schema does not return. Terminal control was rerun because the orphan and repeated-cancellation changes exercise that behavior directly.

The adapter review compares an original mutant only when its file, unchanged contiguous source, location columns, operator and replacement can be matched. Rewritten logic produces new variants. Reported timeouts, Vitest test-deadline failures and schema import errors retain their separate evidence. The exact IDs and status transitions are recorded in the [adapter classification](./mutation_testing_workflow_adapters_classification.json).

## Residual interpretation

- **Ownership and journal integrity.** Direct assertions cover stale tokens, wrong-task mutations, transaction rollback, revision conflicts, signal consumption and outbox identity. Removing a defensive query projection can still return the same presence/absence decision while transferring a wider row. The `SELECT EXISTS` fast-path guard covers a missing result row outside the statement's normal one-row contract.
- **Child admission and terminal trees.** A second PostgreSQL connection checks that a child admission owns the intended advisory lock and leaves independent keys available. Terminal tests cover orphan and partial links, closed parents, retained capacity and bounded cyclic traversal. Remaining reconciliation conditions concern already-persisted children and partial storage states normally excluded by atomic activation. They are retained as guards for externally supplied storage, with status and location preserved in the index.
- **Admission and availability.** The memory wakeup queue keeps at most one workflow task per execution. The reservation loop still checks for duplicate or concurrently owned activations, so variants in those extra checks need a store state outside the ordinary enqueue contract. The PostgreSQL start CTE resolves one row for every normalized request. Remaining start mutants concern its defensive cardinality checks and the default transport literal. The key partition defect was reproduced directly under all three policies because a TypeScript string mutation does not exercise alternate SQL partition expressions.
- **Dispatch, history and continuation.** Tests distinguish absent output from explicit null, preserve completion order and reject old generation writes. Mutation variants that change only an explicit false on a field already set by a built-in schema default can preserve the public result. Read and reserve assertions verify observable filters, lineage, archive order, date type, lease ownership and pagination without pinning diagnostics or every SQL projection.
- **Static schema and adapter definitions.** Migration contracts exercise table ownership, singular names, storage columns, lease timestamps, default values and unique predicates. Of the 101 static import errors, 83 removed a required description and 18 removed or invalidated a schema object, table description or column reference. Forty survivors infer the same column name or timestamp mode. The other three replaced the UUIDv7 SQL default, now checked by ordinary schema assertions added after the measured snapshot.

TypeScript mutation can change Drizzle arguments and whole SQL template literals. Storage invariants also rely on PostgreSQL constraints and transaction interleavings, so the direct connection and journal assertions provide evidence independently of the mutation count.
